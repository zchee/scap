## W3.0b — the `.git` detection default

Deviation D-6 made this a Phase-3 obligation: the two strategies were never
compared directly, because W0.2 measured only open-and-scan and the shipped
jwalk walker only stat-first, and the corpora disagree about how much I/O each
costs. The rule was to measure both at `N*` = 4 on a′ and a+b and freeze the
default from those numbers.

### The matrix (run `20260829T124726Z-p3-w30b`, binary `250b292e`)

| Corpus | | open-and-scan | stat-first |
| --- | --- | --- | --- |
| a′ | median wall | 19.048 ms | **12.072 ms** |
| | user / sys | 6.411 / 44.994 | 4.204 / 22.264 |
| a | median wall | 117.031 ms | **115.035 ms** |
| | user / sys | 31.755 / 407.942 | 32.544 / 398.727 |
| a+b | median wall | 146.618 ms | **141.900 ms** |
| | user / sys | 39.416 / 507.988 | 39.523 / 492.542 |

**Stat-first wins every corpus.** The plan's expectation — that opening a
candidate pays for itself on a directory-dense tree, where most directories
have to be opened anyway — does not survive the measurement: a+b holds 21,360
directories against 1,822 repositories, the shape open-and-scan was predicted
to win, and it loses there too. An `openat` that returns a descriptor costs
more than a `statat` that returns `ENOENT` by more than the saved probe is
worth, at both corpus shapes this machine can offer.

### Replication, because the a+b margin is thin

The a+b bounds sit within a few milliseconds of the measured medians, so the
decisive rows were taken four times in the same window rather than once.

| Sample | n | stat median (user) | AC-3a/c/d | open median (user) | AC-3a/c/d |
| --- | --- | --- | --- | --- | --- |
| `p3-w30b` | 30 | 141.900 (39.523) | FAIL / FAIL / FAIL | 146.618 (39.416) | PASS / FAIL / FAIL |
| `p3-w30b-rep` | 30 | 137.311 (37.831) | PASS | 147.837 (39.845) | FAIL / FAIL / FAIL |
| `p3-threads` (`t4`) | 30 | 136.436 (37.682) | PASS | 150.755 (40.144) | FAIL / FAIL / FAIL |
| `p3-tighten` | 60 | 138.267 (38.078) | PASS | 146.311 (39.322) | PASS / FAIL / FAIL |

Open-and-scan fails the two wall legs in **all four** samples, by 6.3 to
10.7 ms. Stat-first passes in three of four; its one failure is the first
sample of the window, and it misses by 1.365 ms of wall and 0.105 ms of user
CPU. The 60-run row — the same instrument that cleared the Phase-2
`root_pinned_root_cwd` caveat in the Phase-2b window — reads 138.267 ms
[134.994, 140.739] with margins of +1.792 (AC-3c), +2.268 (AC-3d) and +1.339
(AC-3a). The failing sample is recorded rather than dropped: the honest
statement is that stat-first clears the a+b bounds by roughly 1.6 % of wall,
not that it clears them comfortably.

On a′ the separation is not thin at all. Against the frozen W2b.1 reference
(12.245 ms, IQR 12.001-12.714) open-and-scan reads 19.048 and 19.147 ms with
IQRs disjoint from it and bootstrap intervals of [+6.162, +7.331] and
[+6.388, +7.317] ms — entirely positive, i.e. a reproducible regression
against the walker Phase 3 inherits. Stat-first's intervals overlap zero or
sit inside the tolerance the D-6 form allows. **Open-and-scan could not be the
default on that leg alone.**

### Decision

> **W3.0b frozen: default = stat-first.** Open-and-scan survives as
> `SCAP_LIST_DETECT=open`, an ADR-13 override, because the measurement is one
> filesystem and one corpus shape — around twelve directories per repository —
> and a tree far sparser in repositories is where it could still win.

Applied in `b4fb566` `perf(walk): freeze the default .git detection strategy`,
which also adds the README and CHANGELOG rows and a test naming the frozen
answer, so re-deciding it requires re-measuring rather than editing one
attribute.

## The thread rule, re-derived on the shipped walker

Decision B's rule: `N*` is the smallest `N` whose median wall is within
1.10× of the best, subject to `sys(N) ≤ 1.5 × sys(1)`. Run
`20260829T125135Z-p3-threads`, corpus a+b, 30 runs per point.

**stat-first** — best wall 127.414 → clause bound 141.155; `sys(1)` 341.194 →
sys bound 511.791:

| `N` | median wall | IQR | user | sys | wall clause | sys clause |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 367.186 | 362.391-375.344 | 27.328 | 341.194 | no | ok |
| 2 | 204.917 | 198.133-208.361 | 30.680 | 367.798 | no | ok |
| **4** | **136.436** | 132.041-140.150 | 37.682 | 467.669 | **ok** | **ok** |
| 8 | 127.414 | 125.745-128.537 | 51.393 | 867.830 | ok | no |

**open-and-scan** — best wall 139.064 → bound 152.970; `sys(1)` 355.806 → bound
533.709: N = 1 382.124 (no/ok), N = 2 218.388 (no/ok), **N = 4 150.755
(ok/ok)**, N = 8 139.064 with sys 953.288 (ok/no).

`N*` = **4** for both strategies, which is the pool's shipped default. Eight
threads buy 9 ms of wall for 400 ms of system time and are exactly what the
sys clause exists to refuse.

The a′ wall leg reads on its overlap arm rather than its absolute arm, and the
reason is worth stating plainly: **the frozen reference is not reproducible in
this window.** The preserved W2b.1 binary `0b48c24a`, re-measured here
(`20260829T125022Z-p3-ref`), reads **12.896 ms** on a′ against its own frozen

(60 runs) sits at a paired CI of [-0.511, +0.561] ms — statistically
indistinguishable — while using 4.491 ms of user CPU against the reference's
12.518. The overlap arm D-6 introduced is doing exactly the job it was created
for: guarding against regression without pinning a wall figure that the
machine itself does not hold still.

## Counter semantics: `dirs_read` now follows the default

`dirs_read` counts directories whose entries were read, so it counts
repository directories only under open-and-scan. With stat-first frozen as the
default it reads **1,198** on a′ — reproducing the jwalk walker's count
exactly, which is continuity evidence across three walkers — and 2,042 under
`SCAP_LIST_DETECT=open`. Both are under AC-9's 2,100 bound. The figure
compares within a strategy, never across strategies or across versions, and
the CHANGELOG line that declared it changed at Phase 3 is corrected to say so.

## The measurement window

One window, 2026-08-29 12:46-13:07 UTC, twelve groups, each taking its own D-1a
decision and none forced. Two refusals are on the record and both are the gate
working: `p3-w30b` was refused at 12:46Z with the busiest process at 31.6 %
and passed on retry, and the first `p3-gate-list` group passed its start gate
but ended at 73.4 % idle — contention that appeared mid-group — so its rows
(`list_ab` 147.495, `list_aprime` 15.029) are recorded as contaminated and are
**not** the gate rows; `p3-gate-list-b` re-took them in the clear.

The watchdog between rows and groups never fired: no foreign `hyperfine` and
no foreign sweep driver appeared in the window, and the binary's sha256 was
verified before and after every group, so no group can have measured a
different program from the one it names.

## CodSpeed

No local CodSpeed run was made for Phase 3, deliberately. The two divan suites
cover repository-input parsing and the in-process configuration load — neither
touches the walker this phase rewrote — and the whole-program `scap root` /
`scap list` walltime targets that would cover it cannot run on this host:
`Failed to install exec-harness version 1.3.0 … there isn't a download for
your platform` on `aarch64-apple-darwin`, observed twice in the Phase-2b
window and deterministic. That layer is CI-only by design. Running
`cargo codspeed build` here would also have overwritten the measured
`target/release/scap`, the hazard the Phase-2b document records; the binary
this document names is the one every row above was taken on.
