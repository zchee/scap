## Binary fingerprints

Built in `/Volumes/tmpfs/scap-wt-<commit>` git worktrees (kept off the primary
worktree, which stayed on `HEAD`), plain `cargo build --release` under the
RUSTFLAGS above, one commit at a time, in sequence, worktree removed before
the next build. `size`'s `__TEXT` column is the actual compiled machine code.

| Commit | Size | `__TEXT` | sha256 |
| --- | --- | --- | --- |
| `78b3212` (W1.2) | 2,517,888 B | 1,884,160 B | `eb75a35e6c9eebe7512504c45c051cd7748866e65bc048b9d1d6e33e8828b1ee` |
| `21eb825` (W1.3) | 1,611,776 B | 1,212,416 B | `7eb0789c4de765a11bac66236b1c62943210932d1d6bba92e1b4457aa607637e` |
| `6ab9038` (W1.4) | 1,619,808 B | 1,212,416 B | `3634cbc2391cc5100a2b2d41e2fa7a8abf9013afbf87ea5c36ac99b5441bf2b1` |

**Finding, not a regime failure.** The ledger's expected fingerprints
(`#8`/`#9` NOTES) were produced building in place at
`/Users/zchee/rust/src/github.com/zchee/scap`; the ones above were built in a
tmpfs worktree at a different absolute path, per this task's instructions, so
as not to disturb the primary worktree's checked-out `HEAD`. Every `__TEXT`
value above matches its expected value exactly (1,884,160 / 1,212,416 /
1,212,416) — the compiled instructions are byte-identical. Total size matches
for `78b3212` but is 160 B and 176 B smaller than expected for `21eb825` and
`6ab9038`, and every sha256 differs from the ledger's recorded value
(`d2eb8054…`, `6d8b7a16…`, `64a67fb5…`). `strings` on all three binaries finds
no embedded absolute build path; `nm` shows Rust v0-mangled symbols with
`Cs<hash>` `StableCrateId` disambiguators, a hash cargo derives in part from
the package's absolute path via `-C metadata`/`-C extra-filename`. Building at
a different absolute path than the original in-place builds changes that
hash, which changes symbol-table bytes in `__LINKEDIT` (and, via the ad-hoc
code-signature size that covers it, the total file size) without touching a
single instruction in `__TEXT`. RUSTFLAGS and rustc are confirmed identical
(`rustflags_match: true` in every run's `metadata.json`; `rustc 1.100.0-nightly
(e457a7b0d 2026-08-27)`), so the D-4 regime itself reproduced; what did not
reproduce is a build-path-dependent artifact the D-4 regime was never scoped
to control. Flagged to the team lead before measuring; not re-verified against
an in-place build, to avoid disturbing the primary worktree's `HEAD`.
