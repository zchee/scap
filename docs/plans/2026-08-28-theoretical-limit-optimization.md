## 1. Requirements Summary

R1. Every command reaches its measured floor **by default** (`SCAP_CONFIG_BACKEND=git` excepted): process start (already ≈floor); **zero `git` subprocesses other than the VCS operation itself** for any configuration **without url-scoped `[scap "<url>"]` sections that scap can see and without any of the ADR-8 spawn triggers** (the common case, including this machine and every test fixture); `list` reads no directory the user has excluded and, if Phase 3 passes its gate, walks at the readdir floor with a measured thread count.
R2. `list` stdout stays byte-identical to `ghq list` for every flag combination (`-p`, `-e`, `--unique`, `--bare`, query, `--vcs git`) on the real corpora and the tests/parity_ghq.rs fixtures, **including cross-root duplicates** (ghq does not dedup across roots; `--unique` needs the duplicates: cmd_list.go:78-110). Symlink, root-is-repo, missing-root and unreadable-root semantics are pinned to the ghq oracle in Phase 0 before being frozen in ADR-9.
R3. `get` keeps atomic clone + per-target lock + exit 75 (README "Compatibility" table) and keeps shelling out to `git` for clone/pull/fetch (ADR-3 confirmed).
R4. Config precedence unchanged: `$SCAP_ROOT` → `scap.root` (multi, reversed) → `~/scap`; `scap.<url>.root` urlmatch (delegated to git only when such sections exist, else git's plain-key fallback reproduced in-process); `scap.user`; `scap.completeUser` (src/config.rs:22-58, :61-82, :97-106). New keys are flat (`scap.listExclude`, `scap.listCache`) because ghq's keys are flat (`ghq.completeUser`) and because a `[scap "list"] root = …` section would be misread as a urlmatch root for the URL `list` by the `^scap\..+\.root$` filter (src/config.rs:109); every new key/flag/env is registered in ADR-13 and, when shipped, in the README "Compatibility" table.
R5. `unsafe` (only if Phase 3 takes the B1 path — **it did not: B2 was adopted, so R5 reduces to "there is no unsafe"**) confined to `src/walk/sys.rs`; `// SAFETY:` on every block; crate root `#![deny(unsafe_code)]` with module-level `#![allow(unsafe_code)]` on that one file (never `forbid`, which cannot be overridden — E0453); `#![deny(unsafe_op_in_unsafe_fn)]`, `#![deny(clippy::undocumented_unsafe_blocks)]`. **The B3 path and the B2 path ship zero `unsafe`.**
R6. Tests: sibling `*_tests.rs` files, real git/fs only, every `pub fn` covered (automated check), no new `#[ignore]`; the 20 currently-ignored tests are each promoted (passes against the oracle) or deleted with a one-line reason in the commit body.
R7. Benchmarks are reproducible artifacts: quiet-machine protocol script, hyperfine JSON under `docs/benchmarks/`, wall (mean, median, IQR) + user + sys reported, one loaded-machine row per phase, and cwd-depth rows for config resolution.
R8. Every heuristic that trades exactness for speed has an override: `SCAP_LIST_THREADS`, `--no-cache`/`SCAP_LIST_CACHE=0`, `SCAP_CONFIG_BACKEND=git`, and exclusions are root-relative patterns the user wrote.

Out of scope: non-git VCS backends (ADR-2), gist support (`2026-08-27-scap-gist-clone-support.md` rebases onto W1.1), in-process clone, non-macOS CI (follow-up).

## 2. RALPLAN-DR summary

### Principles
P1. **Measure, then cut** — for every commit touching `src/walk/`, `src/index.rs`, `src/cmd/list.rs`, or `src/config.rs`/`src/config/`, regardless of commit type, a before/after number from the Phase-0 harness is recorded in the commit body (W1.3 records the AC-1 row; its *gate* remains V-1 + AC-6 because it deletes code without changing behaviour except the codecommit dispatch, which is oracle-tested). Commits outside those paths (W1.1, W1.2, W1.4) are gated by V-1 plus the AC-6 startup guard.
P2. **Syscalls are the currency.** User-space work is ≤10 % of `list` CPU today; the design minimises syscall count and kernel lock contention; the thread rule carries an explicit sys budget; config resolution carries an explicit syscall budget (ADR-8).
P3. **Parity is a test, not a feeling — for git repositories.** The ghq binary is the oracle for git-only fixtures; when a scap-only test disagrees with the oracle, the oracle wins and the test is rewritten. ghq's non-git markers (local_repository.go:218-228) remain out of scope (ADR-2). Where ghq crashes (ADR-9 rule vi, third case) it cannot be the oracle and scap's behaviour is registered in ADR-13.
P4. **Unsafe is a leaf, never a trunk** (R5) — and only if measurement earns it (W3.0).
P5. **Every heuristic has an escape hatch** (R8) — including the config backend.

### Decision drivers (top 3)
D1. **Wall time for `list` (median, quiet harness) and per-invocation latency for the other commands**, on corpora a, b, a+b, and a′ (= a minus every path under `github.com/zchee/claude-code.bak/`).
D2. **Parity risk** — probability that a change alters `list`/`root`/`get` destination output vs ghq.
D3. **Maintenance surface** — crates, unsafe lines, platform branches. Recorded as accepted cost where D1 wins; never a gate (mandate).

### Options per decision

#### Decision A — gitconfig access (supersedes ADR-5)

Why A4 beats A3-as-default (AR1): A1's cost was dominated by the urlmatch port (D2) and the crate closure (D3). A4 removes the port entirely and keeps the closure, which the mandate makes a report rather than a gate; what remains is a 7.7–9 ms D1 win on every invocation vs A3 (the in-process parse costs ≈0.1 ms, §0), with the residual D2 (parser + probe) covered by oracle tests (i)–(vi) and every uncertain condition routed to A3 automatically. ## 4. Pre-mortem (3 failure scenarios)

### S1 — The index lies: a repo vanishes from `scap list` with `scap.listCache = true`
**Path to failure:** NFS attribute caching; 1–2 s mtime granularity; `touch -t` backdating. Restores are mostly detected: a Time Machine restore creates new inodes (root `st_ino` mismatch ⇒ full invalidation); `rsync -a --delete` over the root in place rewrites a changed directory's mtime to the *source's* mtime, which is newer than the cached value whenever the source's contents changed — the undetectable residue is "mtime equal, contents different".
**Detection:** mutation matrix (§5; incl. `rsync -a --delete`, `cp -p`, `touch -t`); `--cache-check`.
**Mitigation:** opt-in (ADR-10), `--no-cache`, README row (AC-10), root `st_dev`/`st_ino` guard, 2 s racy window; the `touch -t` row is asserted as a *documented failure* (`--cache-check` exit 1).

### S2 — The walker diverges from ghq on an exotic entry
**Path to failure:** (b) a `.git` gitfile in a directory whose own name ends in `.git`; (c) non-UTF-8 entry names; (d) root itself a repo; (e) dangling symlink, symlink loop, dangling `.git` symlink; (f) permission-denied directory; (g) non-existent / unreadable / non-ENOENT-failing root. Residual, not oracle-fixturable: (a) `DT_UNKNOWN` filesystems — unit test only; (g3) the non-ENOENT root, where ghq panics — scap's behaviour is asserted directly (ADR-13).
**Detection:** W0.4 oracle probe freezes rules (iii)–(vi); tests/parity_ghq.rs fixtures for (b)–(g); corpus diff (V-4) empty, with V-4 failing (not skipping) when `ghq` is absent.
**Mitigation:** bytes end-to-end; symlinks never descended; ignored symlink tests resolved in W2b.2.

### S3 — In-process config resolves a different root than `git config`
**Path to failure:** an `includeIf` condition, a `~user/` expansion, a relative `include.path`, `completeUser` valueless or `yes`, the system-config probe, or `root_for_url` canonicalising a plain root that git prints raw (the v3 defect, item 1).
**Detection:** ADR-8 oracle tests (i)–(vi) over both backends; `scripts/config-parity.sh` (W2.1) compares `scap root --all` with `ghq root --all` and default vs `SCAP_CONFIG_BACKEND=git` on the maintainer's real config.
**Mitigation:** spawn triggers route uncertain configs to A3 automatically; `SCAP_CONFIG_BACKEND=git`; the A3 ship-fallback rule.

## 10. Follow-ups
- **W5.1 — recover the four-thread user CPU, profile-first.** The walk spends 11.34 ms of user CPU at `N` = 4 that it does not spend at `N` = 1, which is 30 % of the measured figure and 29 % of AC-3a's budget, against a post-processing span of 0.17 ms and a fixed startup of 1.135 ms. **Where it goes is an open question, not a diagnosed one.** W3.5b named two values in `src/walk/pool.rs` as the cause, rewrote them, and measured no change; counting the pool's own execution then showed the idle/steal path running ≈ 1,000 times per walk over ≈ 70 idle episodes, which cannot carry 11 ms (`docs/benchmarks/2026-08-29-w35b.md`). **This item may not be reopened with another guess.** It is gated on the W3.5c profile probe (#21f), whose verdict — the delta concentrated in identifiable frames, or spread uniformly and therefore environmental — decides whether there is anything here to recover.
